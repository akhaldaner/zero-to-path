# Petition Template

A petition is a compact service record generated by the subject mentor after verifying the learner's work. The learner does not compose it manually. The learner inserts it into the daily log.

## Form

PETITION
id: {{artifact_id}}
subj: {{SUBJ}}
type: {{DRL|UNT|EXM}}
req: mastered
crit: independent={{yes|no}} | test={{result|tasks}} | written=mentor_approved | verify={{method}} | error={{yes|no|na}}
note: {{optional}}

## Rules

- `independent=yes` is mandatory.
- `written=mentor_approved` is mandatory.
- `test` is mandatory: test result or completed tasks.
- `verify` is mandatory: numeric check, code run, exit status, answer check, experiment output, or equivalent.
- `error=na` is allowed only when error analysis is not applicable, for example a pure exam.
- If any element is missing, the subject chat does not submit a petition.
- The subject chat does not set `mastered` in the map. It only proposes it.

## Example

PETITION
id: PROG-DRL-01-conditionals
subj: PROG
type: DRL
req: mastered
crit: independent=yes | test=8/10 | written=mentor_approved | verify=code run + prediction check + edge cases | error=yes
note: basic conditionals drill
